# Plan 03-01: Loader Integration

## Goal

`device_spec_loader.py`에 3가지 기능을 추가한다:
1. `ModuleMeta` 데이터클래스 + `DeviceSpec.module_meta` 필드
2. requires/conflicts 위반 시 logging.warning 출력
3. YAML 로드 시 jsonschema로 스키마 자동 검증

**선결 버그 수정 포함**: 현재 `_load_command_group()`이 `meta:` 키를
일반 CmdEntry로 처리하여 cmdset에 "meta" 항목이 추가되는 버그 존재 → 동시에 수정.

## Context

- Phase 2에서 11개 command YAML에 `meta:` 블록 추가 완료
- jsonschema 4.26.0 설치 확인 (`uv run python -c "import jsonschema"` 통과)
- device_spec_loader.py: 410줄, DeviceSpec 데이터클래스 중심 구조

## Tasks

### Task 1: 버그 수정 + ModuleMeta 구현

1. `import json`, `import logging` 추가
2. `_schema_cache: dict[str, dict] = {}` 모듈 레벨 캐시 추가
3. `ModuleMeta` 데이터클래스 추가 (FWConfig 뒤)
4. `DeviceSpec`에 `module_meta: dict[str, ModuleMeta]` 필드 추가
5. `_parse_module_meta()` 헬퍼 추가
6. `_load_command_group()` 수정:
   - `meta:` 키 건너뜀 (버그 수정)
   - `ModuleMeta | None` 반환 포함 → `tuple` 반환으로 변경
7. `_load_device_impl()` 수정:
   - `_load_command_group()` 반환값 언패킹 처리
   - `module_meta` dict 수집
   - `DeviceSpec(... module_meta=module_meta)` 추가

### Task 2: requires/conflicts 검증

1. `_validate_module_compatibility()` 함수 추가
2. `_load_device_impl()` 에서 그룹 로딩 후 호출

### Task 3: 스키마 자동 검증

1. `_get_schema()` 헬퍼 (파일 캐싱) 추가
2. `_validate_yaml_schema()` 헬퍼 추가 (jsonschema 없으면 skip)
3. `_load_command_group()` 에서 `command-group.schema.json` 검증 호출
4. `_load_device_impl()` 에서 `device.schema.json` 검증 호출

### Task 4: jsonschema → requirements.txt 추가

`requirements.txt`에 `jsonschema==4.26.0` Runtime 섹션 추가.

### Task 5: __main__ 테스트 보강 + 커밋

`__main__` 블록에 `module_meta` 접근 예시 추가 후 커밋.

## Acceptance Criteria

1. `load_device("WIZ107SR").module_meta["base"].name == "Base Commands"`
2. 잘못된 command_groups 조합 시 `logging.warning` 출력
3. 구조가 잘못된 YAML 로드 시 스키마 오류 메시지가 warning 로그에 출력
4. 기존 `uv run python device_spec_loader.py` 전체 통과 (회귀 없음)
5. `uv run python validate_schemas.py` 전체 통과 유지
