# WIZnet S2E Tool GUI — 구형 장비 통합 지원 보고서

**버전:** v1.6.0 → v1.6.2.3  
**작성일:** 2026-05-19  
**대상:** 내부 배포

---

## 배경 — 왜 구형 장비 지원을 강화했는가

WIZ1xx / WIZ5xx / WIZ7xx 시리즈는 단종 또는 구형으로 분류되지만,
**2020년 이후에도 총 40만 건 이상의 판매가 지속**되고 있습니다.

| 시리즈 | 해당 장비 | 2020~2026 누적 판매 | 2025~2026 판매 |
|--------|----------|--------------------:|---------------:|
| WIZ7xx | WIZ107SR / WIZ108SR | 약 182,000 | 약 49,000 |
| WIZ1xx | WIZ100SR / WIZ105SR / WIZ110SR | 약 194,000 | 약 23,000 |
| WIZ5xx | WIZ550SR / WIZ550S2E / WIZ550WEB | 약 31,500 | 약 7,000 |
| **합계** | | **약 407,500** | **약 79,000** |

*(판매량 단위: Qty)*

2025~2026년만 놓고 봐도 **약 79,000대**가 현장에 납품되었습니다.
이 장비들을 운용 중인 고객은 설정·펌웨어 업그레이드·모니터링을 위해
기존 도구(WIZnet S2E Tool GUI)를 계속 사용해야 하지만,
구형 장비 지원이 미비하거나 별도 툴이 필요한 상황이었습니다.

이에 따라 **"하나의 툴에서 구형·신형 장비를 통합 관리"** 를 목표로
v1.6.0~v1.6.2.3에 걸쳐 세 시리즈를 순차적으로 지원했습니다.

## 1. WIZ107SR / WIZ108SR (WIZ7xx) 지원 — v1.6.0

### 판매 현황

WIZ7xx는 세 시리즈 중 **가장 큰 규모**로 판매되고 있는 시리즈입니다.
2021년 최고 약 39,000대를 기록한 이후 등락을 반복하면서도,
2025년 약 31,000대로 재반등하며 꾸준한 현장 수요를 보이고 있습니다.

### 지원 이전의 문제

기존 툴은 WIZ5xxSR 계열 커맨드 구조만 지원했기 때문에,
WIZ107SR / WIZ108SR 사용자는 VB.NET 기반의 별도 ConfigTool을 병행해야 했습니다.
PPPoE 모드, DDNS 설정, Telnet 전환 등 WIZ107/108 고유 기능은
기존 툴에서 전혀 설정할 수 없었습니다.

### 구현된 개선 사항

**커맨드 세트 통합**
- WIZ107SR / WIZ108SR 전용 42개 커맨드 세트(`cmd_107sr`) 신규 추가
- DDNS 설정 커맨드 (DD·DX·DP·DI·DW·DH), PPPoE 커맨드 (PI·PP·IM=2) 지원
- Telnet / TCP Raw 전환 (PO 커맨드) 지원
- TR(Transfer) 커맨드 제외 및 UI 숨김 처리 (펌웨어 미지원)

**하드웨어 제약 자동 적용**
- 9-bit 데이터 비트 선택 시 parity=NONE, stop=1-bit 자동 강제
- 최대 보드레이트 230,400 bps 제한 자동 적용
- PPPoE 모드 선택 시 IP·게이트웨이·서브넷 필드 자동 비활성화

**독립 설정 툴 제공**
- VB.NET ConfigTool 107 v1.4.4.1을 Python으로 완전 포팅
- `107_108_config/` 독립 모듈로 제공 (`uv run python -m 107_108_config`)
- 기존 VB.NET 툴 의존성을 Python 환경으로 대체

## 2. WIZ100SR / WIZ105SR / WIZ110SR (WIZ1xx) 지원 — v1.6.1

### 판매 현황

WIZ1xx는 2022년 약 46,000대로 정점을 찍은 이후 감소세이나,
**2020~2026 누적 약 194,000대**로 세 시리즈 중 **총 판매량이 가장 많습니다.**
현장에 이미 납품된 장비 수를 고려하면 유지보수·설정 변경 요청은 장기간 지속될 전망입니다.

### 지원 이전의 문제

WIZ1x0SR은 기존 S2E 시리즈와 **완전히 다른 바이너리 프로토콜**을 사용합니다.
기존 툴(ASCII 커맨드 기반)로는 탐색조차 불가능했으며,
사용자는 시리얼 터미널로 직접 명령을 입력하거나
단종된 구버전 Windows XP 전용 툴에 의존해야 했습니다.

### 구현된 개선 사항

**바이너리 프로토콜 완전 구현**
- FIND / IMIN / SETT / SETC 바이너리 프로토콜 (UDP 포트 1460) 신규 구현
- `WIZ1x0MSGHandler.py` — 프로토콜 전용 QThread (비동기 송수신)
- `WIZ1x0Profile.py` — 163-byte 바이너리 구조체 파서·빌더

**전용 UI 패널**
- Network / Serial / Option 3-탭 전용 패널 — 기존 S2E UI와 완전 분리
- 검색 결과 목록에 하늘색 배경으로 WIZ1x0SR 행 시각 구분
- Apply / Reset / Upload 버튼 라우팅 자동 분기

**실 장치 테스트 중 발견한 프로토콜 버그 8건 동시 수정**

| 버그 | 증상 | 수정 내용 |
|------|------|----------|
| BOARD_INFO_SIZE 오류 | 검색 시 장치 전혀 탐색 안 됨 | 163 → 159 바이트 수정 |
| 수신 소켓 INADDR_ANY 미설정 | 서브넷 달라지면 응답 미수신 | INADDR_ANY 바인딩 |
| SETT unicast 전송 | 장치가 설정 명령 수신 못함 | broadcast 전송으로 수정 |
| NIC IP 바인딩 누락 | 멀티홈 환경에서 응답 누락 | 선택된 NIC IP로 바인딩 |
| WinError 10048/10049 | 반복 검색 시 소켓 오류 | 소켓 재사용 설정 추가 |

## 3. WIZ550SR / WIZ550S2E / WIZ550WEB (WIZ5xx) 지원 — v1.6.2.2

### 판매 현황

WIZ5xx는 절대량은 작지만 **2023년 약 7,000대로 정점** 이후
2025~2026년에도 연 약 3,500대 수준을 꾸준히 유지하고 있습니다.
특히 WIZ550WEB(HTTP 기반 설정)과 WIZ550S2E(MQTT/Modbus 지원)는
산업용 IoT 환경에 소규모 납품되는 특성상 사후 설정 변경 요청이 빈번합니다.

### 지원 이전의 문제

WIZ550 시리즈는 전용 UDP Discovery 프로토콜(포트 6550)과
XOR 암호화 헤더를 사용하며, Java 기반 원본 툴만 지원 가능했습니다.
Python/PyQt5 기반 현행 툴과 완전히 호환되지 않아
별도 Java 런타임 설치와 구버전 툴 유지가 필요했습니다.

### 구현된 개선 사항

**프로토콜 엔진 신규 구현**
- `WIZ550MSGHandler.py` — Discovery / GET_INFO / SET / Reset QThread
- XOR 암호화(매 패킷 랜덤 키) 완전 구현 — Java 원본 소스 역분석 기반
- Java 원본의 payload length MSB 버그 우회 로직 적용

**3종 구조체 파서·빌더**
- WIZ550SR: 162-byte 고정 구조체
- WIZ550S2E: 162-byte 기본 + Modbus(+2B) / MQTT(+70B) 가변 확장
- WIZ550WEB: 133-byte (UART 2채널 독립 설정)

**기존 UI 재활용으로 학습 비용 최소화**
- WIZ550 선택 시 기존 generalTab UI 그대로 활용 (별도 화면 없음)
- Apply / Reset / Factory Reset 기존 버튼 동작 그대로 연결

## 4. 전체 기능 개선 사항

구형 장비 지원과 함께 전체 도구의 완성도를 높이는 기능이 추가되었습니다.

### 4-1. FW from Git — GitHub에서 직접 펌웨어 다운로드

장치 선택 후 GitHub Releases 목록에서 펌웨어를 선택하면
다운로드부터 업로드까지 자동으로 연결됩니다.
USB 드라이브 또는 수동 파일 관리 없이 최신 펌웨어 적용 가능.

### 4-2. 내장 터미널 패널 — 외부 툴 의존 제거

Serial / TCP / UDP 터미널을 툴 내부에서 바로 사용할 수 있습니다.
기존에는 Hercules, PuTTY 등 외부 툴을 별도 실행해야 했습니다.

- 매크로 시퀀스 저장·불러오기 (최대 8개 프리셋)
- TX / RX 바이트 통계
- `Ctrl+T` 단축키로 즉시 열기

### 4-3. 보안 강화 — 악의적 패킷 대응

| 항목 | 내용 |
|------|------|
| HIGH-01 | 비정상 패킷 수신 시 크래시 방지 |
| HIGH-03 | UDP 응답 파싱 무한 루프 방어 |
| HIGH-04 | 펌웨어 응답 파싱 오류 방지 |
| BOOT 차단 | BOOT 이미지 업로드 시 경고 후 차단 |

### 4-4. DeviceSpec YAML — 신규 장비 추가 구조 개선

장치별 커맨드·UI 설정을 YAML 파일로 정의하는 구조로 전환.
이후 신규 장비 추가 시 코드 수정 없이 YAML 파일만 추가하면 됩니다.
