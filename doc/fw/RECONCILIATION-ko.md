## 담당자 질문 — 통합안 (원래 약 25개 → 담당자별 5개 이내)
소스로 답이 나왔거나 이미 확정된 것(BR 14, IP20/W232N 저장소 위치, 752 RH/QH 공유)은 뺐다.

**4CH / W55RP20 담당**
1. 확인 GET 응답이 1,792B 를 넘으면 SV/RT 가 조용히 사라지는 것은 의도인가? 툴 대응 선택지 3개 (`QUESTIONS-4ch-fw-owner-ko.md` Q1).
2. `memset(segcp_rep, 0, CONFIG_BUF_SIZE)` 가 헤더 뒤 포인터부터라 `gSEGCPREP` 끝을 넘는가 — 링커 맵의 다음 심볼 (Q2).
3. 미구현 명령 응답이 4B(전언) 인가 5B(소스)인가 (Q3).
4. 4port 의 두 보호(`SEGCP_REPLY_HEADROOM`, `segcp_store_string`)를 main/2Port/GreenCS 에 이식할 계획이 있는가. `DH`·`SP` 초과를 거부로 둘지 자를지 포함.
5. 2Port·GreenCS 명령표가 `"0"` 로 끝나는 것은 의도인가.

**WIZ750SR / 752SR 담당**
1. RH 길이검사 수정 계획 (750 `[49]`, 752 `[40]`) — 툴은 48/39 로 막아 둠.
2. 512B 초과 시 덮이는 메모리, 현장 증상 유무.
3. 오류 시 `return ret` 로 SV/RT 가 스킵되고 ER 줄이 응답에 실리는 현재 동작이 의도인가(브랜치 `fix/user-io-and-segcp` 병합 계획).
4. `SS` 소문자 16진이 틀린 값으로 저장되는 `str_to_hex` 를 고칠 계획이 있는가.
5. 권한 모델(MA=FF…으로도 SET/SV/RT)과 `K!` 가 의도인가.

**WIZ5XXSR-RP 담당** (현 담당은 인수받은 사람 — 지적이 아니라 "이 파일 이 줄을 열어 보시면" 형식으로)
1. 현장 출하 바이너리가 `board.h` 의 GPIO 옵션 꺼짐 상태로 빌드되는가(`CA~GD` GET 공백).
2. `PS` 상한: 툴 255 / FW 2048 — 제품 사양은 어느 쪽인가.
3. E-SAVE 현재 기준 소스 위치.
4. UDP 1,472B 초과 응답 단편화 동작(W5100S).

**WIZ550 담당**
1. **현장에 WIZ550S2E v1.2.x 가 있는가** — v1.2.0·1.2.1 에 MQTT 필드가 있어 툴의 짝수=Modbus 판별이 맞지 않을 수 있다.
2. S2E/Modbus 의 UDP SET baud 상한이 하드웨어 사양인가 AT 검사만의 제약인가(460800 등).
3. SET 응답이 저장 완료를 보증하는가(저장이 응답보다 먼저인 구조의 의미).
